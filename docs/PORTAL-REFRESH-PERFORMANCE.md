# Portal refresh performance investigation

Review 27 remains the verified playable package. The shipping probe's combat P95 was 44.061 ms. A focused profile on the unchanged executable reproduced a combat 39.082 ms P95 (18.404 ms mean), with no garbage collections during combat. Portal submission averaged 5.266 ms with 15.125 ms P95; scripts and physics also slowed during affected frames. Inclusive timings are not additive, synchronous readback is included and GPU samples are unavailable. This identifies substantial portal work, not a proven single root cause of every spike.

Four combat-view destination cameras each rendered every frame although their apertures were only about 11–58 pixels tall. The opt-in candidate reuses distant small views for two or four frames, with a 1/15-second age limit. Close (within 12 m), large (96 pixels on the longest side) and scoped views refresh every frame. Re-entry, view/projection/layer changes, aperture escape from cached crop, resizing and invalid targets force a refresh. Cached texture and shader crop coordinates stay paired. No movement, teleport, collision, damage or multiplayer authority changes.

The candidate is disabled by default and only enabled by --profile-portal-refresh in the attribution harness. Native frozen-map checks cover all six directions: non-black destination images, zero pixel differences between full-rate and cached images, close/scoped full cadence, projection/layer/movement/re-entry gates and actor invariants. Four pure policy checks cover thresholds, screen-edge crop containment and phase distribution. A test setup that reset a physical camera's projection also needed its physical-lens mode restored before checking focal-length-based ADS; that diagnostic is not a game projection fix.

Source: PortalView.cs and PortalRefreshPolicy.cs. Reproduce focused checks through PortalRefreshPolicyTests and PortalRefreshRenderingReview. Run tools/Profile-PortalRefresh.ps1 with a new output folder in both orders against one unchanged candidate. It hashes nine runtime payload files before and after each run and verifies embedded build identity/mode. tools/compare_portal_refresh.py validates the workload and keeps nearby portal 0 at full cadence. The current study is pending measurement and promotion; this document does not establish a sustained 60 FPS or artistic acceptance result.
